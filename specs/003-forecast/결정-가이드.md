## 먼저: "모델을 학습한다"는 게 뭔가

과제 2의 '현재값 유지'는 **사람이 정한 규칙**이었다. "60분 뒤 값 = 지금 값"이다.

딥러닝 모델은 규칙을 사람이 쓰지 않는다. 대신 **빈칸이 아주 많은 계산식**을 하나 둔다.

- 이 계산식은 입력(지난 2시간 CO₂ 등)을 넣으면 숫자 12개(5분 뒤 ~ 60분 뒤)를 낸다. Java로 치면 `double[] predict(double[][] past)` 같은 함수다.
- 처음에는 빈칸(가중치)이 아무 숫자라서 엉터리를 낸다.
- 지난 1년 치에서 "이때 입력 → 실제로 일어난 60분"을 수만 개 꺼내 보여 준다.
- 틀린 만큼 빈칸을 조금씩 고친다. 이걸 수없이 반복하는 게 **학습**이다.
- 학습 기간(~2026-08)으로 고치고, 검증 기간(9월)으로 "어느 설정이 나은지" 고르고, 시험 기간(10월)으로 마지막에 한 번 채점한다.

PyTorch는 이 "빈칸 많은 계산식"을 만들고 고치는 도구(라이브러리)다.

### 무엇을 예측하나: 문제 만들기 → 연습 → 모의고사 → 시험

**1. 문제 만들기.** 1년 2개월 데이터를 통째로 한 번에 예측하는 것이 아니다. 데이터를 잘라 **문제 수만 개**를 만든다.
- 문제 1개 = "이 시각(t)까지 2시간을 보고, t 뒤 60분(12칸)을 맞혀라"
- t를 5분씩 옮기면 문제가 하나씩 생긴다. 2025-09-03 02:00, 02:05, 02:10, …
- 정답(뒤 60분 실제 값)은 이미 데이터에 있다. 과거 데이터라서다.
- 학습 기간(약 1년)에서만 공간마다 약 10만 개가 나온다(긴 결측이 낀 문제는 뺀다).

**2. 연습 (학습, 2025-09 ~ 2026-08).**
- 문제 몇십 개를 모델에 풀게 한다 → 정답과 비교해 오차를 잰다 → 오차가 줄어드는 쪽으로 빈칸을 조금 고친다.
- 이것을 문제집(학습 기간 문제 전체) 끝까지 한다. 한 바퀴를 **에폭(epoch)**이라 부른다.
- 같은 문제집을 여러 바퀴(수십 번) 돈다. 돌수록 연습 문제 오차는 계속 준다.

**3. 모의고사 (검증, 2026-09).**
- 한 바퀴 돌 때마다 9월 문제를 풀려서 점수만 본다. 9월 문제로는 빈칸을 고치지 않는다.
- 연습 점수는 오르는데 모의고사 점수가 더 안 오르면, 문제를 외우기 시작한 것이다(과적합). 거기서 멈추고 모의고사 점수가 가장 좋았던 때의 빈칸을 남긴다.
- 여러 설정(GRU/LSTM/TCN, 과거 1·2·4시간) 중 무엇이 나은지도 모의고사 점수로 고른다.

**4. 시험 (2026-10-01 ~ 10-21).**
- 다 고른 뒤 **딱 한 번** 푼다. 빈칸도 고치지 않고 설정도 바꾸지 않는다. 이 점수가 보고서의 점수이고 기준선과 비교하는 숫자다.
- 시험 점수를 보고 다시 고치면, 시험 문제에 맞춘 셈이 되어 실제 실력보다 좋게 나온다(확인 기준 SC-003).

**5. 실제 사용 (과제 8 서비스).**
- 정답이 아직 없는 진짜 미래를 5분마다 예측한다. 빈칸은 학습 때 정한 그대로 쓴다.

## Q2. 모델 종류 — LSTM, GRU, TCN

셋 다 **시간 순서대로 들어오는 값**을 다루는 계산식의 모양이다. 차이는 "과거를 어떻게 훑어보느냐"다.

이 셋을 **모델 구조**(architecture)라고 부른다. 빈칸이 어디에 몇 개 있고 입력이 어떤 순서로 계산되는지를 정한 '틀'이다. 빈칸을 채우는 **학습 방법**(틀린 만큼 조금씩 고치기)은 셋 다 똑같다. Java로 치면 구조는 클래스 설계, 학습이 끝난 빈칸 값은 객체에 채워진 필드 값이다.

### 먼저: RNN과 CNN은 무엇인가

둘 다 **신경망**(빈칸 많은 계산식을 여러 겹 쌓은 것)의 큰 갈래다. LSTM·GRU는 RNN 갈래, TCN은 CNN 갈래에 속한다.

예로 실습실 CO₂ 6칸(30분)이 이렇게 들어왔다고 하자: `500, 520, 560, 610, 650, 700`.

**RNN (Recurrent Neural Network, 순환 신경망)**
- 같은 작은 계산기 하나를 칸마다 **되풀이해서**(recurrent) 쓴다.
- 계산기는 "지금 칸 값"과 "지금까지의 메모"를 받아 "새 메모"를 낸다.
- 500을 읽고 메모 → 520을 읽고 메모 고침 → … → 700까지 읽은 뒤의 메모로 예측한다.
- Java로 쓰면 이런 모양이다.

```java
double[] memo = new double[64];          // 처음엔 빈 메모
for (double x : co2) {                    // 오래된 칸부터 하나씩
    memo = cell.update(memo, x);          // 같은 계산기(cell)를 매번 다시 씀
}
double[] forecast = head.predict(memo);   // 마지막 메모로 60분 예측
```

- 앞 칸을 끝내야 다음 칸을 계산할 수 있다. 그래서 칸이 많으면 느리고, 아주 오래전 칸은 메모가 여러 번 덧칠되며 흐려진다. LSTM·GRU의 '문(gate)'은 이 흐려짐을 줄이려고 만든 장치다.

**CNN (Convolutional Neural Network, 합성곱 신경망)**
- 몇 칸짜리 작은 **창(필터)**을 처음부터 끝까지 밀면서, 창 안의 값에 가중치를 곱해 더한다. 이것을 합성곱(convolution)이라 부른다.
- 예: 창 3칸, 가중치 `-1, 0, +1`이면 "3칸 사이에 얼마나 올랐나"를 재는 창이 된다. `500,520,560` → 60, `520,560,610` → 90, … 위치마다 따로 계산한다.
- 이런 창을 여러 개 두면 "오르는 중", "꺾이는 중", "평평함" 같은 모양을 동시에 찾는다. 가중치는 사람이 정하지 않고 학습으로 정해진다.
- 층을 쌓으면 위층 창 하나가 아래층 여러 칸을 보게 되어, 점점 긴 과거를 본다. TCN은 칸을 건너뛰며 보는 창(dilation: 1칸, 2칸, 4칸 간격)으로 적은 층으로 긴 과거를 본다.

**창 모양.** 사진용 CNN은 창이 3×3 같은 격자이고 가로·세로 두 방향으로 민다. 우리 시계열에서는 창을 **시간 방향으로만** 민다. 다만 입력이 CO₂·온도·습도·일정 등 여러 줄이라서, 창 하나는 "모든 항목 × 3칸"을 한꺼번에 덮는다. 예를 들어 항목이 3개면 창은 3×3 격자 모양이다. 위아래(항목 방향)로는 밀지 않는다. 항목 순서는 의미가 없어서 "CO₂ 옆에 온도"라는 위치 관계를 볼 이유가 없기 때문이다.

```
           t-4  t-3  t-2  t-1   t
CO₂       [ .    .  ][ .    .    . ]    ← 창은 항목 줄을 전부 덮고
온도      [ .    .  ][ .    .    . ]      오른쪽(시간)으로만 한 칸씩 민다
습도      [ .    .  ][ .    .    . ]
                      └ 창 1개(항목 3 × 3칸)
```

**층 쌓기.** 층을 쌓는다는 것은 창을 크게 만드는 것이 아니다. 1층 창들이 낸 결과 줄을 2층 창이 다시 훑는 것이다.

```
2층 (2칸 간격 창)          ●                     2층 칸 1개 = 원래 7칸을 봄
                     ┌─────┼─────┐
1층 (1칸 간격 창)    ●     ●     ●               1층 칸 1개 = 원래 3칸을 봄
                   ┌─┼─┐ ┌─┼─┐ ┌─┼─┐
입력 칸            ● ● ● ● ● ● ●   (t-6 ~ t)
```

간격을 1, 2, 4, 8칸으로 늘려 4층을 쌓으면 원래 31칸(약 2시간 반)까지 본다. 이것이 TCN의 '칸 건너뛰기(dilation)'다.

```java
for (int t = 2; t < co2.length; t++) {    // 위치마다 서로 독립 → 한꺼번에 계산 가능
    out[t] = w0*co2[t-2] + w1*co2[t-1] + w2*co2[t];
}
```

- 원래 사진 처리에서 시작했다(사진의 작은 네모 창을 밀며 모서리·무늬 찾기). 시계열은 1줄짜리 사진이라고 보면 된다.

**비교**

| | RNN (LSTM, GRU) | CNN (TCN) |
|---|---|---|
| 읽는 방식 | 한 칸씩 차례로, 메모를 넘기며 | 창을 밀며 모든 위치를 한꺼번에 |
| 비유 | 일기장을 넘기며 메모 | 일기장을 펼쳐 놓고 돋보기 여러 개 |
| 먼 과거 | 메모로 이론상 끝까지 이어짐. 대신 흐려지기 쉬움 | 창이 닿는 범위까지만 봄. 범위는 설계할 때 정함 |
| 계산 속도 | 칸끼리 차례를 기다려야 해서 GPU 장점을 덜 씀 | 위치끼리 독립이라 GPU에서 빠름 |
| 입력 길이 | 아무 길이나 그대로 받음 | 창 범위보다 길면 앞부분은 안 봄 |
| 우리 과제에서 | 과거 2시간(24칸)이면 충분히 빠름 | 과제 7(Jetson, TensorRT)에서 더 빨라질 가능성 |

표의 '한꺼번에'는 **계산을 동시에 돌릴 수 있다**는 속도 이야기다. 목표가 여러 개라는 뜻이 아니다. 창 3칸 계산은 위치마다 서로 기다릴 필요가 없어서, Java의 스레드 여러 개처럼 GPU가 위치 24개를 동시에 계산한다. 결과는 한 칸씩 차례로 계산한 것과 똑같고 시간만 줄어든다. 여러 목표를 함께 맞히는 것(예: CO₂와 온도를 한 모델이)은 RNN·CNN 둘 다 할 수 있으며 Q8에서 고른다.

과거가 24칸 정도로 짧으면 둘의 실력 차이는 대개 크지 않다. 그래서 심화(B)에서 직접 돌려 비교하는 것이 의미가 있다.

### LSTM, GRU — 한 칸씩 읽으며 메모하는 방식 (순환 신경망, RNN)

- 사람이 일기장을 앞에서부터 한 장씩 넘기며 **메모장**에 중요한 것만 적어 가는 것과 같다.
- 5분 칸을 오래된 것부터 하나씩 읽는다. 읽을 때마다 메모를 고친다. 예: "지금 CO₂가 오르는 중", "점심이 끝났다".
- 마지막 칸까지 읽은 뒤의 메모를 보고 60분을 예측한다.
- 메모장에는 "무엇을 지우고 무엇을 남길지" 정하는 문(gate)이 있다.
  - **LSTM**: 문이 3개, 메모장도 2권이다. 오래된 것을 더 잘 기억하지만 계산할 게 많다. 1997년에 나와 가장 널리 쓰였다.
  - **GRU**: LSTM을 줄인 것이다. 문이 2개, 메모장이 1권이다. 계산할 게 약 25% 적고 실력은 대개 비슷하다(2014년).
- 약점: 한 칸씩 차례로 읽어야 해서 칸이 많으면 느리다. Jetson GPU처럼 여러 계산을 한꺼번에 하는 장비의 장점을 덜 살린다.

### TCN — 창문 여러 개로 한꺼번에 보는 방식 (합성곱, CNN 계열)

- 일기장을 펼쳐 놓고 **돋보기 여러 개**로 동시에 보는 것과 같다.
- 작은 돋보기는 "최근 15분 동안 올랐나"를 보고, 큰 돋보기는 "1~2시간 전부터 흐름이 어땠나"를 본다.
- 모든 위치를 한꺼번에 계산할 수 있어서 GPU에서 빠르다. 과제 7(TensorRT 변환) 뒤에 더 빨라지는 경향이 있다.
- 미래 칸을 몰래 보지 않도록 "과거 쪽만 보는" 돋보기를 쓴다. 그래서 이름이 Temporal(시간) Convolutional(합성곱) Network다.
- 약점: 돋보기가 닿는 범위(과거 길이)를 설계할 때 정해야 한다.

### 고를 것

심화(B)라서 **셋 다 학습해서 비교한다**. 여기서 고르는 것은 **무엇부터 만들지**(먼저 기본 확인 기준을 채울 모델)다.

| 선택 | 그러면 |
|---|---|
| GRU 먼저 | 셋 중 가장 작고 단순하다. 빨리 첫 결과를 본다 |
| LSTM 먼저 | 가장 유명하다. GRU보다 조금 무겁다 |
| TCN 먼저 | 구조가 이미지 처리와 비슷하다. 순서대로 읽는 방식과 생각이 다르다 |

추천: GRU 먼저. 셋 중 가장 작아서 결과를 빨리 볼 수 있다.

## Q3. 과거를 얼마나 볼까 (입력 길이)

모델에게 "지난 몇 시간"을 보여 줄지다. 5분 칸이라 1시간 = 12칸이다.

- 짧으면(30분, 1시간): 계산이 가볍다. 하지만 "점심 끝나고 다시 오르는 중"처럼 긴 흐름을 못 볼 수 있다.
- 길면(4시간, 하루): 흐름은 다 보지만 학습이 느리고, 쓸데없는 옛날 값에 헷갈릴 수 있다. 하루치를 보려면 빈 칸이 없는 표본이 줄어든다.

심화(B)는 **1·2·4시간을 모두 비교**하게 돼 있다. 여기서 고르는 것은 **처음 시작할 길이**다.

| 선택 | 그러면 |
|---|---|
| 1시간 | 가장 가볍다 |
| 2시간 | 오전 수업 시작~점심 전처럼 한 덩어리가 보인다 |

## Q6. 60분을 한 번에, 아니면 한 칸씩

예측해야 하는 것은 5분 뒤, 10분 뒤, … 60분 뒤 12칸이다.

- **한 번에(direct)**: 모델이 숫자 12개를 동시에 낸다.
- **한 칸씩 반복(recursive)**: 모델이 5분 뒤 하나만 낸다. 그 값을 진짜인 것처럼 입력 끝에 붙여서 다시 5분 뒤를 낸다. 12번 반복한다.

**시각으로 보는 예** (지금이 13:00, 과거 2시간을 본다)

한 번에:
```
입력: 11:00 ~ 13:00 진짜 값 24칸
모델 1번 호출 → 13:05, 13:10, … 14:00 (12칸) 한꺼번에
```

한 칸씩 반복:
```
1번째 호출: 입력 11:00~13:00 (진짜)              → 13:05 예측값
2번째 호출: 입력 11:05~13:00 (진짜) + 13:05(예측) → 13:10 예측값
3번째 호출: 입력 11:10~13:00 (진짜) + 13:05·13:10(예측) → 13:15 예측값
… 12번째 호출에서 14:00 예측값
```
뒤로 갈수록 입력에 진짜 값 대신 모델이 지어낸 값이 섞인다.

**어느 방식이든 예측은 60분까지만 한다.** 14:00 다음(14:05 이후)을 예측값으로 이어 붙이지 않는다. 5분 뒤 13:05에 진짜 값이 들어오면 11:05~13:05 진짜 값으로 13:10~14:05를 **처음부터 새로** 예측한다. 과제 8 서비스도 이렇게 매번 새로 예측한다.

| 선택 | 좋은 점 | 나쁜 점 |
|---|---|---|
| 한 번에 | 빠르다(1번 계산). 앞 칸 실수가 뒤로 번지지 않는다 | 12칸이 서로 안 이어져 보일 수 있다(대개 문제 없음) |
| 한 칸씩 | 모델이 작다. 몇 칸이든 늘릴 수 있다 | 5분 뒤를 10ppm 틀리면 그 틀린 값으로 다음을 맞히므로 60분 뒤에는 오차가 쌓인다. 계산이 12번이라 과제 8 서비스가 느려진다 |

**왜 '한 번에'가 대개 오차가 적은가.** 한 번에 넓은 범위를 계산해서가 아니다. **60분 뒤 값을 무엇을 보고 맞히느냐**가 다르다.
- 한 번에: 60분 뒤 값을 **진짜 값 24칸**만 보고 맞힌다. 학습 때도 "진짜 값 → 60분 뒤 정답"으로 직접 연습한다.
- 한 칸씩: 60분 뒤 값을 맞힐 때 입력 끝 11칸이 **모델이 지어낸 값**이다. 그런데 모델은 학습 때 진짜 값만 보고 연습했다. 자기가 지어낸 값을 입력으로 받는 상황은 연습한 적이 없다.
- 예: 모델이 5분마다 오름을 2ppm씩 덜 예측하는 버릇이 있다면, 한 칸씩 방식은 그 덜 오른 값을 다음 입력으로 쓰므로 버릇이 겹친다. 12번째 칸에서는 24ppm 이상 차이가 날 수 있다. 한 번에 방식은 60분 칸을 따로 연습했으므로 이렇게 겹치지 않는다.

**늘 그런 것은 아니다.** 한 칸씩 방식은 "5분 뒤 하나"만 배우면 되어 배우기가 쉽다. 데이터가 적거나 5분 예측이 아주 정확하면 한 칸씩이 이길 때도 있다. 그래서 확실히 하려면 둘 다 돌려 비교할 수 있다(심화에서 비교표에 넣기 가능).

추천: 한 번에. 60분 예측이 진짜 값만 보고 나오고, 계산도 한 번이면 된다.
