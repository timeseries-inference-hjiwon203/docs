# 시계열 데이터 추론 실습 Constitution

교육장(강의실 2, 회의실 1, 라운지 1)의 CO₂·온도·습도 센서 데이터로
"지금 무슨 일이 일어나고 있고, 곧 어떻게 될까"에 답하는 추론 서비스를 만들어
Jetson Orin Nano(aip-1)에서 상시 운영한다.
이 문서는 모든 과제(1~8)에 공통으로 지키는 원칙이다.

## Core Principles

### I. 기준선 먼저 (Baseline-First)

모델을 만들기 전에 단순한 기준선(현재값 유지, 최근 1시간 평균, 어제 같은 시각)의
성능을 먼저 잰다. 기준선을 이기지 못하는 모델은 채택하지 않는다.
모든 모델 결과는 같은 시점·같은 조건에서 기준선과 나란히 비교한다.

### II. 공정한 평가 (No Leakage) — 반드시 지킴

- 학습·검증·시험 기간은 시간 순서로 나눈다. 무작위로 섞지 않는다.
- 정규화 값(평균·표준편차)은 학습 기간 데이터로만 계산한다.
- 시험 기간 데이터는 학습에도, 모델 선택에도 쓰지 않는다.
- 정답을 만든 정보(예: 일정)를 같은 문제의 입력으로 넣지 않는다.

### III. 결과마다 해석 (Interpretation)

"돌려 봤더니 이렇게 나왔다"로 끝내지 않는다. 결과마다
**왜 이렇게 나왔는지**와 **그래서 무엇을 해야 하는지**를 함께 쓴다.
모델이 못하는 것도 정확히 적는다.

### IV. 측정 조건 기록 (Reproducibility)

모든 결과표에 측정 조건을 함께 적는다:
데이터 기간, 실데이터/합성 데이터 여부, 시험 기간, 보드 전력 모드.
성능 측정에는 클럭 고정 여부, 반복 횟수, 워밍업도 적는다.

### V. 사람 손 없이 계속 돈다 (Resilience)

수집기와 추론 서비스는 브로커 재시작, 네트워크 끊김, 보드 재부팅 뒤에도
스스로 다시 시작한다. 데이터가 끊기면 멈추지 말고 끊긴 사실을 알린다.

### VI. 설정으로 바꾼다 (Config over Code)

메시지 형식 변경이나 센서 추가에는 프로그램이 아니라 설정을 고쳐 대응한다.
학습과 서비스는 같은 전처리를 쓴다.

### VII. 단순하게 시작 (Simplicity)

가장 단순하게 동작하는 것을 먼저 만들고,
심화(B) 항목은 기본(A)이 끝난 뒤에 붙인다.

## 보안·운영 제약

- 토큰·비밀번호는 저장소(git)에 올리지 않는다.
- 보드 한 대(메모리 8GB)를 여러 사람이 계정을 나눠 쓰고, 시계열 모델·임베딩 모델·로컬 LLM이 함께 올라간다. 메모리 예산을 의식한다.
- Jetson에 프로그램을 설치할 때는 무엇인지, 왜 필요한지, 안 깔아도 되는 경우를 함께 기록한다.
- 결과는 다른 팀이 문서만 보고 쓸 수 있어야 한다(토픽·필드·단위·예시).

## 작업 흐름

1. 과제마다 `specs/NNN-이름/` 폴더에 `spec.md`(무엇을) → `plan.md`(어떻게) → `tasks.md`(할 일 목록)를 만든다.
2. 과제의 "확인 기준"을 spec의 Success Criteria로 그대로 옮긴다.
3. 과제가 끝나면 산출물(표·그래프·보고)을 해당 폴더에 남기고 `ROADMAP.md` 상태를 갱신한다.

## Governance

이 원칙은 모든 과제의 계획보다 우선한다. 원칙을 바꿀 때는 이 파일을 고치고
버전과 날짜를 올린다.
